# How to Contribute

Thanks for taking a look at this project and considering to contribute your time and effort to it! It means a lot.
But before you start making wild PRs, take a look at the short guide below to know how to best contribute.

### Pull Requests
Each pull request (PR) should implement only a single change or feature.
The amount of code in a single PR should be a manageable amount to read and review.

If a feature requires more than what could be considered manageable, consider splitting it into multiple PRs that merge into a feature branch.
That feature branch can be merged into main once it is complete.

### Tasks
Development will be focused on a single feature set at a time.
Look at the project's Kanban Board for what tasks need to be done, and claim a task if it tickles your fancy.

### Branches
Create a new branch for any feature/ticket you wish to implement and push your work to it.
When complete, create a PR for that branch to `main`.
Once all comments from project owners are addressed, it can be merged.

### New Libraries
The addition of new libraries should be done in a controlled manner.
If there are any that will make implementing a feature much easier, contact the owner to discuss it.
Don't add any without asking first.

Update `$root/spotless/spotless.importorder` with the new library after adding it
